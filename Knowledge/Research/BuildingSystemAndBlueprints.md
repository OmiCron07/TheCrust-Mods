## Goal
Place modules, conveyor belts and electric wires programmatically as vanilla ghosts (planning mode) and capture them back from the world.

## Verified Facts
- **Grid**: 400 x 400 cells of 100 uu. `CellId = Row * 400 + Col`, Row grows with world X, Col with world Y. Underground pivot Z = 0, Crater pivot Z = 6001. `ECDirection`: 0 Up (-Row), 1 Right (+Col), 2 Down (+Row), 3 Left (-Col). Yaw +90 (vanilla `RotateModule(true)`) maps (dRow, dCol) -> (-dCol, dRow).
- **Layers**: `GodPlayer_PC.CurrentGameLayer` 0 Underground, 1 Orbital, 2 Crater. Conveyor managers: `PC.ConveyorManagerUnderground` / `PC.ConveyorManagerSurface` (`BP_ConveyorManager_C` : C++ `AConveyorManager`). `Level:GetGroundManager(TorchLocation)` takes 1 for underground, 0 for crater.
- **Modules** (`ModuleBase_BP_C` : `AModuleBase`): footprint in `CellIndexesUnderModule` (IO cells included, some listed twice), IO cells in `IOCells[i].CellId`. `BuildingStateCPP` 0 NotSettledYet ... 4 Finished, 6-8 dismantle. `"Settled Module"` is only true for modules placed this session (false after load). `IsCopyAllowed` = unlocked and built by player, or planned; electric pillars placed with the wire tool (C) never get `IsBuildedByPlayer` and are rejected by it.
- **Ghost module placement** (vanilla `PlacingModule LMB Click`): `PC:SpawnModuleOnLocation(Class, CellId)` -> optional `MirrorModule()` -> rotation -> `"Snap Module to Cursor"(Location)` -> validation -> `bPlanningModeCPP = bInPlanningMode = true` -> `SettleModule()` -> `IsBuildedByPlayer = true`. Hide the leftover validity squares with `Undercells[i]:SetVision(false)`.
- **Unsettled module as a hologram** (paste preview): a module from `SpawnModuleOnLocation` (`BuildingStateCPP` 0) already renders as the vanilla blue building-mode hologram and follows rotation + `"Snap Module to Cursor"`. A few frames after spawning it gets screen-space `W_IOCell_Resource_C` icons (yellow "?" squares, `"My Module"` = the module) that stay at their creation position instead of following the snap (observed while paused). Collapse them from a post-hook on `/Game/Widgets/ConveyorCommonWIdgets/W_IOCell_Resource.W_IOCell_Resource_C:Set My IOCell` (params `IOCell, MyModule`; `SetVisibility(1)`); `"Switch IOCells Widgets Niagara"(false)` does not hide them. They vanish when the module is destroyed. `FindAllOf("W_IOCell_Resource_C")` costs ~28 ms, too slow to poll.
- **Belt meshes**: `CM.SectionVisualManager` / `CM.HoloSectionVisualManager` (`UCSectionVisualManager`) draw belts with `UBeltHISM` per `ECVisualCellType` (1 BeltLine, 2 Corner, 3 Splitter, 5 UndergroundBelt, 6 Pillar...) via `GetHismByTypeAndLevel(Type, UpgradeLevel)`. Built and holo HISMs share the same meshes and materials (`M_Conveyor_Inst`, `M_Conveyor_belt_Inst`; `HoloMaterialInstance` is null): the look comes from 16 per-instance custom data floats. `[3]` is 1 on every belt; `[8] = [9] = 1` built, `[9] = [10] = 1` planning ghost, `[9] = 1` alone the blue holo. A plain `InstancedStaticMeshComponent` added with `AddComponentByClass(..., bDeferredFinish = true)`, `NumCustomDataFloats = 16` written before `FinishAddComponent`, the source mesh + materials and `SetCustomDataValue` renders like vanilla; a `UBeltHISM` added the same way kept the built look whatever its custom data (likely its unbuilt instance tree; `BuildTreeIfOutdated` is not exposed to Lua). `AddInstances` / `BatchUpdateInstancesTransforms` accept Lua arrays of FTransform tables. Instance Z = grid Z + `ConveyorHeight` (-5).
- **Belt visual yaws** (measured with `GetSectionVisualArrays(Section, OutTransforms, OutTypes)`, one entry per section cell): BeltLine `(2 - Dir) * 90`; Corner touching sides A and A+1 (side = direction from the cell, flow ignored) `(3 - A) * 90`; Splitter 0; UndergroundBelt `-D * 90`, D pointing at the other end; Roadblock (unconnected section end) faces outward: start `(2 - Out) * 90 + 180`, end `(2 - In) * 90`.
- **Module mirroring** (vanilla `T`, input action `PC_Module_Mirror`; `MirrorModule()` is C++-side, the BP stub only jumps into the ubergraph): sets actor scale X = -1 and `IsMirrored = true`, i.e. flips the **local** row axis before the yaw (measured: yaw 0 maps dRow -> -dRow, yaw 90 maps dCol -> -dCol). Modules with `bCanMirror = false` (`MB_OneResourceStorage`, `MB_BigBulkStorage`) ignore it: scale and flag stay. A whole-layout mirror in a frame then a yaw T equals each module at yaw -T with its mirror flag toggled (F R(T) = R(-T) F). `IOCells[i].CellId` of an unsettled module is stale (not updated by snapping); read IO positions on settled modules only. Storage IO cells sit on all four sides, so an unmirrorable storage keeps its IO positions under a layout mirror but the IOCells index of each side changes (settings must be remapped by position).
- **Placement validation** (vanilla `TickFunctionForPlacingModuleMode`): when `CPPPlacementCheck` is false (`MB_ExtractorDeepOre` always returns false) vanilla only uses the module's `CheckIfCanSettleModuleAccordingToUndermoduleCells` override (extractor: at least `DT_GenerateVeinsSettings.MinimalCellCountForDeepOreExtractor` active cells on mineral fields) plus the count limit. Otherwise: `CPPPlacementCheck`, underground only `"Check Intersection Of Perimeter Cells and Soil"`, `CheckIfCanSettleModuleWithInteriorSettings`, `CheckPossibilityOfModuleSettlementAccordingToGM(GroundManager, GetAnchorCellCurrentRealID)`, `PC:CheckIfCanSettleCuzOfThisTypeModulesCount`. `CheckIfCanSettleModule` is NOT used by vanilla and wrongly rejects Big Bulk Storage.
- **Production scheme** = APS ability string: `AbilityAgencyVar."Active APS Ability"` (built) or `AbilityBeforeBuilt` when `bChangedRecipieBeforeBuilt`. Apply with `AbilityAgencyVar:ExecuteAbility(Name, nil)` (works on ghosts), as vanilla `Copy-PasteSettings` does.
- **Conveyors**: sections in `BuiltSectionStates` / `HoloSectionStates` (`FCSectionState`: `CellIds` in flow order, `LineDirections`, `CornerCellIDs`, `Type` 1 belt / 2 distributor / 3 underground belt) after `UpdateSectionStates()`; per cell via `SectionGrid` / `HoloSectionGrid :GetSectionAtCellID_Safe(Cell)`.
- `AConveyorManager:BuildHolo(Start, End, bVertical, false, -1)` creates holo (unbuilt, blue) belts: straight or L with `bVertical` choosing the first leg (the `CornerCellID` argument is ignored). It never creates underground belts. Sections from separate calls are NOT connected, even adjacent and collinear (`MergeEverything` does not link them), unless a call **starts or ends on a cell of an existing belt** (any earlier call, not only the previous one): starting on its last cell or ending on its first cell from behind skips the shared cell and links both sections, also around a turn; starting or ending on a middle cell, or a second belt starting / ending on the same end cell, turns that cell into a **distributor** (`Type` 2, one cell, inputs / outputs derived from the adjacent belts, existing sections split around it). A 2-cell call between two adjacent distributors links them. `MainPointerAction` in `ECInputMode` 4 (Distributor) with a computed location does nothing (and removed holo belts in one test). A section never accepts input on the side of its first cell. Remove a holo with `CM:DeleteHoloSectionAtCellID(Cell)`.
- **Holo deferred state** (white planning ghost vs blue holo the build button pays for): a new holo section is deferred iff `BP_ConveyorManager:GetDeferModeActive()`, which returns `GodPlayer_PC.bIsPlanningModeActive` (the global planning toggle, also shown in the belt menu); `AConveyorManager.bDeferModeActive` is not read. Writing the PC field around `BuildHolo` works.
- **Underground belts** (`Type` 3): a pair of one-cell sections linked by `ConnectedUndergroundBeltCellID`; both ends look identical (each `LineDirections[1]` points at the other end, `IsEndOfUndergroundBeltLine()` false on both), the flow is given by connections only (entry has `InputToSectionCells`, exit `OutputFromSectionCells`). Create with the vanilla tool from Lua: `CM:SetConveyorMode(3)`, `CM.Controller:ResetClickCellIDs()`, `CM:RotateUndergroundBelt(false)` until `Controller:GetUndergroundBeltDirection()` is the flow (each call: 2 -> 1 -> 0 -> 3), then `CM:MainPointerAction(Location)` on the entry then the exit (location = cell center, grid Z). `UConveyorController:MainAction(Cell)` only records the click. Connections follow the BuildHolo rule: a belt ending on the entry cell or starting on the exit cell links; a belt ending next to the entry does not; an exit next to another entry (or a distributor) links with a 2-cell `BuildHolo(Exit, Entry)`. `DeleteHoloSectionAtCellID` removes an end. Max distance `UndergroundBuildSectionLength` (8).
- **Test pitfall**: `BuildHolo` silently creates nothing when any cell of the shape is covered by a module (planning ghosts included); check `Placer.Occupancy` before blaming parameters, and never clear test areas next to the player's builds.
- **Distributor settings** (UI `W_ConveyorDistributorRenewed` / `W_ConveyorDistributor_Input`, all on the `UCSection`): `OutputArrID` = 0-based index into `State.OutputDirections`, which also indexes `State.OutputAllowedResources` (`FCAllowedResources`: `ResourceTypesAllowed`, `bPriorityOutput`, `bLockedOutput`, `bHandTunedOutput`, `bUserBlockedOutput`); indices follow connection order, so store settings by `ECDirection`. Setters: `CM:AddResourceTypeAtOutput(Id, S, Type)` (UI path, also `RemoveResourceTypeAtOutput`), `S:SetIsHandTunedOutput`, `SetIsPriorityOutput`, `SetUserBlockedOutput`, `SetOutputLocked`, `SetOutputPriority(Id, Level)`, `SetInputPriority(InputArrID, Level)` (index into `InputDirections`). Levels: 0 high, 1 default, 2 low, stored by direction in `State.DistributorPriorityStates.OutputToPriority` / `InputToPriority`. `SetIsPriorityOutput(Id, true)` also sets that output's level to 0, so set the level after it. Filters do not propagate to holo belt `ResourceTypesAllowed`. Building 7 holo cells including one distributor costs 2500 credits.
- **Module IO cell settings** (UI `W_ConveyorOutputSetting`, on `BP_CIOCell_C`, same `IOCells` order for every module of a class, planning ghosts included): output filter `ResourceOutputFiltrationArray` (`"Execute Clear Resource Output Filtration Array"()`, `"Add In Resource Output Filtration Array"(Type)`), lock `bLocksOutput` (`"Setter Bool by Tag"({TagName = FName("ObjectType.IOCELL.Bool.LocksOutput")}, Bool)`), overflow `Get_bOverflow()` (`"Flip OverflowState"({})`), IO swap = which `StorageModuleAgency` the cell feeds (`Module:Execute_SwapIOCells(IO1, IO2, {})` rebinds agencies, same IOType only). Default bindings are not name-matched: `MB_EnrichmentFactory` `AluminumOxideOutput` -> `SAO_Slag`, `SlagOutput` -> `SAO_AluminiumOxide`. Vanilla copy/paste settings (GodPlayer_PC `Copy-PasteSettings`) only copies the production scheme.
- `UCSection:SetDeferred(true)` marks the planning flag (white "planning" look) but the visual only refreshes after a save reload; `bDeferModeActive`, input mode 8 and pointer actions did not make deferred holos from script.
- **Electric wires**: `Level.ElectricManager` (`AllNodesCPP`, `AllLinks` with GUID-suffixed fields `StartNode_7_...`, `EndNode_8_...`). Module node: `Module.ElectricNodeActor.Node.NodeID`. Vanilla link: `SetCurrentLinkStartNode`, `SetCurrentLinkEndNode`, `"Add Link"`, `AddLinkToItsNodes`, `"Add Neighbours By Link"`, `DrawCurrentLinkPersistent`, `ClearCurrentLinkInfo`.

- **Start construction of a ghost** (vanilla play button): `"Available For Building from PlanningMode"()` (supply + unlock) then `ChangeFromPlanningModeToDefault()`. **Build holo belts**: only `BuildAllConveyors` moves holo sections to the built grid (`BuildAllSectionsWithMoney` = pay total + `BuildAllConveyors`, skipping deferred sections). To build a subset, temporarily `SetDeferred(true)` every other holo section. **`BuildAllSectionsWithMoney` branches on `GetterDefferedMode` (= `PC.bIsPlanningModeActive`)**: off -> `Take Money` + `BuildAllConveyors`; on -> no payment, `BuildAllConveyors` (built nothing in game 2026-10-08) then `ToggleDefferedMode` (C++ `ToggleDeferMode`), which undeferred every holo section of the layer (all planning ghosts became blue holos, `IsSuccess` still true). Write `PC.bIsPlanningModeActive = false` around the call. `SetDeferred(true)` repairs the data, but neither it nor `HoloSectionVisualManager:UpdateSectionsVisual()` refreshes the blue look (save reload does). `BuildSection` / `BuildSectionAtCellID` on a holo section only sets `bBuilt` and leaves it in the holo grid: a built belt and a holo drawn on top of each other (repair: `SetBuilt(false)` then `BuildAllConveyors`).
- **Vanilla demolition tool** (bytecode of GodPlayer_PC `StartDeconstruct`, `LMB for Demolition`, `TickForDemolition`, `ToggleModuleDismantle`): entering sets `SwitchInputMode(11)` + `CM:SetConveyorMode(2)`. Module click: `PC:ToggleModuleDismantle(Module)`; it plays the "don't touch" sound on actors tagged `LockedDemolition`, aborts (`ExecuteDismantleAbort`) when `BuildingAgency.MarkedOnDismantle` is already set, otherwise by `ModuleGlobalState`: `AbilityAgencyVar:ExecuteAbility("ACM_CancelBuilding")` (under construction), `ExecuteAbility("ACM_Dismantle")` (built, robots), or instant `BuildingAgency:StartDestruction()`, `SetupBuildingState(6)`, `EndOfDestruction()` (planned). Built belt click: tick calls `CM:HoverOnDestruction(Cell)` (`_Group` with Shift), which fills `CM.LastDestructionWindowCellIDs`; click calls `CM:DeleteWindowedCells(Cell)` (Shift: `DeleteSectionAtCellID_Group`) then `BP_ConveyorManager:BP_RecoupCollected()` (refund). Holo belt click: `CM:DeleteHoloSectionAtCellID(Cell)` (Shift: `_Group`). Wires: `ElectricManager` remove on a hit `Electric_Link_Visual` when `CanWeRemoveThisLink`.
- **Exact belt deletion from script** (verified in game 2026-10-06): `HoverOnDestruction(Cell)` fills `LastDestructionWindowCellIDs` with a fixed chunk of the section (4-5 cells, same with `SetSelectByCell`). `DeleteWindowedCells(Anchor)` deletes exactly the cells of that array, so `Window:Empty()` + `Window[i] = Cell` (UE4SS TArray writes work) + `DeleteWindowedCells(Cell)` removes any cell set of one built section; the refund accumulates in `BP_ConveyorManager.costToRecoup` and `BP_RecoupCollected()` pays it. Holo belts: `DeleteHoloSectionAtCellID` ignores the array and always removes the chunk containing the cell; `DeleteWindowedCells` does nothing on holo cells. Planned and under-construction modules hit by `ToggleModuleDismantle` are destroyed later in the frame (state and `ModuleGlobalState` unchanged right after the call, `PendingKill` a few frames later). Deleting one end of an underground pair (holo) leaves the other as a lone end with `ConnectedUndergroundBeltCellID` -1 (not deleted with it). A non-deferred holo underground pair stays holo after `BuildAllSectionsWithMoney` (IsSuccess true), unlike regular belts (seen 2026-10-06, cause not investigated).
- **Belt tiers / upgrade** (verified in game 2026-10-06): tier lives on the section, `S.State.ConveyorTier` (0-based) with `State.ConveyorSpeed`. `CM.ConveyorSubsystem:GetConveyorSpeedCount()` = 5; `GetConveyorSpeed(t)` 1 / 2.5 / 5 / 7.5, `GetTierCost(t)` per cell 0 / 500 / 1500 / 3500. Researched cap `CM.MaxConveyorUpgradeLevel` (float, 1.0 in the probed save); `CM.CurrentBuiltUpgradeLevel` stayed 0. Vanilla upgrade from script: `CM:SetConveyorMode(5)`, `CM:OnHover(Loc)` (fills `LastHoveredSections` and `LastSectionUpgradeCost` = cells x tier cost delta), `CM:MainPointerAction(Loc)` -> whole section +1 tier, capped at the researched max (click at max does nothing), works on holo sections too. `CM:UpgradeAtCellID(Cell, false)` alone (mode 0, no hover) did nothing on a holo section. No downgrade exists: right click (`SecondaryPointerAction`) in mode 5 does nothing, and writing `State.ConveyorTier` changes the speed but not the mesh (`VisualManager.CellToUpgradeLevel` unchanged even after `UpdateSectionsVisual()`).

## Pitfalls & Dead Ends
- **`DeleteWindowedCells` with stale cells crashes the game** (EXCEPTION_ACCESS_VIOLATION reading 0x68 in native conveyor code, reproduced 2026-10-06 on 32 built storages with belts on their IO cells): cells grouped per section before deleting, after dismantle orders on the modules, no longer matched their sections. Delete belts before ordering module dismantles, re-read `SectionGrid:GetSectionAtCellID_Safe(Cell).State.CellIds` before every call and pass one contiguous run of that section only.
- **Never call `FindFirstOf` / `FindAllOf` per frame**: they scan the whole GUObjectArray; two calls per frame halved the FPS (120 -> 45). Get the PC from the hooked `GodPawn_C.PlayerControllerRef` and cache the game instance (lives for the whole process).
- After a UE4SS auto-reload that stalled, `ExecuteInGameThread` queues stopped running and a later mod reload hung ("Stopping mod ... for uninstall" never followed by a restart): avoid `ExecuteInGameThread`/`LoopAsync` polling entirely, a game restart is required to recover.
- **UE4SS `IsValid()` stays true for destroyed objects until the next GC** (~60 s): salvaged planned modules (and destroyed preview ghosts) keep `PendingKill` set, are still returned by `FindAllOf`, and keep their `BuildingStateCPP` / `CellIndexesUnderModule`, so occupancy scans saw their cells as taken until GC. Validity check = `o:IsValid() and not o:HasAnyInternalFlags(EInternalObjectFlags.PendingKill)` (`Game.Valid`).
- **GetFName on a null wrapper crashes the game** (EXCEPTION_ACCESS_VIOLATION reading 0x18 = `NamePrivate`). UE4SS returns null wrappers, not `nil`, and `pcall` cannot catch it. Always `type(o) == "userdata" and o:IsValid()` before touching an object.
- **UE4SS auto-reloads a Lua mod when its files change** (`EnableAutoReloadingLuaMods = 1`). Closures queued with `ExecuteInGameThread` (e.g. from `LoopAsync`) outlive the old Lua state and crash the game. Tick from a per-frame `RegisterHook` (e.g. `GodPawn_C:ArmLenght`) and only queue flags from `RegisterKeyBind` callbacks.
- Even with a hook-based tick, the UE4SS auto-reload of a mod hooking `GodPawn_C:ArmLenght` crashes the game most of the time (null read during the new instance's startup, likely hook registration racing the running hook). Restart the game after deploying instead of relying on hot reload.
- UMG `EHorizontalAlignment` / `EVerticalAlignment`: 0 = Fill, 1 = Left/Top, 2 = Center, 3 = Right/Bottom. Game UI look: layered `T_Panel10_White1/2/3` brushes (Box, margin 0.25), buttons `T_Btn_Tab1_n_Saturated` / `_s_` tinted, font `/Game/Fonts/Bahnshrift/bahnschrift_Font` typeface `Default`.
- UObject references (widgets, actors) must be dropped without being touched when the world changes (save load): key the session on `PC:GetFullName()` and idle while `CrustGameInstance_C.LoadingInProcess`.
- UE4SS out params: pass one table per out param; the first one receives all values by parameter name. A lone struct out param (e.g. `GetGridLocationByCellID`) is unpacked into the table (`X, Y, Z`). By-ref struct inputs (`"Add Link"(FLinkStruct&)`) need a Lua table copy, so write the returned `Added Link Id` back into `EM.CurrentLink` before `AddLinkToItsNodes`, or nodes get link id -1.
- `GetGridLocationByCellID` returns nothing for cells outside the level (e.g. cell 0).
- Vanilla input action mappings without modifiers also fire when Ctrl/Shift/Alt are held: `Ctrl+B` triggers belt mode. Use keys the game does not bind (K, I, O, Insert, Delete; `DefaultInput.ini` also binds A/D/S/W) for mod hotkeys; UE4SS names Insert / Delete `Key.INS` / `Key.DEL`.
- `"Debug Execute Cancel Ability"` on a module crashed the game; remove ghosts with vanilla UI tools instead.
- Engine overlay materials (`M_SimpleUnlitTranslucent`, `BasicShapeMaterial`) ignore alpha set through a MID `Color` param: draw outlines, not filled boxes.

## Direct Code / CLI Snippet
```lua
-- Ghost module at a cell (planning mode), rotated a quarter turn clockwise
local Out = {}
PC:SpawnModuleOnLocation(Class, CellId, Out, {})
local M = Out["Out Module"]
M:K2_SetActorRotation({ Pitch = 0, Yaw = 90, Roll = 0 }, false)
M:RecalculateCellIndexesUnderModule(true, {})
local Snap = M["Snap Module to Cursor"]
Snap(M, Location, {})
M.bPlanningModeCPP, M.bInPlanningMode = true, true
M:SettleModule()

-- Holo belt L-shape from Start to End, vertical leg first
PC.ConveyorManagerUnderground:BuildHolo(StartCell, EndCell, true, false, -1)
```
